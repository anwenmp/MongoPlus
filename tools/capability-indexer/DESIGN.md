# 能力分类与实施顺序

2026-10-19 在生成最终能力文件前确定。分类依据：官网功能导航、现有声明索引、当前实现和测试。

| 一级分类 | 二级分类 | 边界 |
| --- | --- | --- |
| 数据读写 | 实体访问、条件查询、分页与结果、更新与批量、原生访问 | 查询条件与执行入口组合成任务能力，不逐方法建条目 |
| 聚合计算 | 管道编排、关联与分支、表达式、编码边界 | 子管道与表达式独立；构建成功不等于服务端合法 |
| 实体与字段映射 | 命名与标识、类型转换、字段增强、关联映射 | 填充、额外字段和字典回写归这里；通用 Handler 的注册契约归扩展 |
| 安全隔离与一致性 | 租户与删除、并发与事务、字段保护、操作保护 | 加密与脱敏作用不同；事务不与异步镜像混同 |
| 扩展与事件 | 执行扩展、命令事件、字段扩展、生命周期 | Driver 命令成功事件不等于事务提交或可靠消息 |
| 连接路由与集成 | 连接配置、数据源路由、集合路由、容器接入、开发工具 | 分片路由与跨源原子事务分开；内部索引工具不可推荐为业务 API |
| 集合运维 | 索引管理、时序集合、备份与镜像、变动记录 | 自动索引与手工索引合并；镜像与导出恢复分别记录 |

重复检查：Mapper/Repository/Service 是同一实体访问能力的不同入口；同一 API 可以复用为多个场景的证据。命令事件和执行拦截按阶段分开。索引类型、加密算法、查询操作符作为能力内部选项，不各建能力。

遗漏检查：遍历声明类型的模块/包摘要，检查注解消费者、默认 Handler、容器资源注册、可选 sensitive-word/sharding 模块及 indexer 工具；无明确业务用途的内部缓存不提升为功能。保留候选和内部条目，不能由 public 可见性推断支持等级。

实施依赖与完成条件：

1. 核对输入结构及哈希，定向读取文档和实现（不重跑 API 扫描器）。
2. 人工维护 catalog.py 中的能力、证据选择器和边界；选择器必须在现有 JSONL 唯一定位类型或真实方法族。
3. 生成 JSONL、导航、未记录清单、分析报告，保存源文件哈希和文档检查范围。
4. 校验引用、行号、状态、分类、重复条目；至少 20 条冻结的需求用例做离线检索及逐例人工评议。
5. 重复生成检查确定性；确认已有产物和业务文件未变。

风险：官网有历史页面/失效链接；测试集中在聚合编码，其他功能多仅能静态核验；声明索引没有调用图；容器 Bean 接线不意味着所有版本组合均已运行。各风险必须反映在条目与报告中。
